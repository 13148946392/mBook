## 一、产品是什么

**一句话**：把麦当劳的餐品数据整理成一份可以抽、可以翻、有收集进度的图鉴。

它回答三个问题：

| 页签 | 回答 | 本质 |
|---|---|---|
| **抽奖** | 今天吃哪个？ | 决策辅助 |
| **图鉴** | 这东西什么来头？ | 资料查询 |
| **活动** | 最近有什么限定？ | 信息聚合 |
| **我的** | 我收集到哪了？ | 个人记录 |

**刻意不做**：不诱导消费、不做自动下单、不做排行榜与社交比较、不碰积分抽奖接口。
产品的胜利条件是「帮你更快决定吃什么」，不是「让你多吃」。

## 二、核心机制

### 抽卡（门面功能）

卡池 = 图鉴全部 158 张卡，四种卡池可切：全部 / 正餐(≥250kcal) / 轻量(<250) / 当季限定。

**稀有度完全由数据算出，无隐藏权重**：

```
LIM  卡名关键词出现在当月活动文本中   ← campaign-calendar
SSR  能量 ≥ 450 kcal 的正餐主力        ← list-nutrition-foods
SR   320–449 kcal
R    150–319 kcal
N    < 150 kcal（多为饮品小食）
```

**限定判定是动态的** —— 每月拉一次活动日历，文本里提到什么商品，它自动变 LIM。当前约 8 张（麦旋风系列、圆筒、薯饼、薯条类），下月换活动自动跟着换，零人工维护。

**两重保底**（标准抽卡心理机制）：
- 十连保底：十张里无 SR+ → 第 10 张强制替换
- 累计保底：连 10 抽无 SR+ → 下一抽强制从 SR+ 池抽，进度条可见

**抽卡零消耗**：纯本地行为，不调任何写接口，不碰积分。

> 与官方「周六麦金喜抽奖」（`draw-lottery`，24 积分/次、当前 809 分可抽 33 次）是两回事，本产品**永不接入**该接口。

### 图鉴（资料功能）

158 条真实营养数据，支持：
- 网格 / 列表双视图
- 三重筛选：属性(8 类) × 稀有度(5 档) × 捕获状态
- 五种排序：热量↓↑ / 蛋白↓ / 钠↓ / 名称
- 属性收集进度（7 条分类进度条）
- **详情弹层**：六大营养素条形图 + 占每日参考值百分比

每日参考值（NRV）：能量 2000kcal · 蛋白 60g · 脂肪 60g · 碳水 300g · 钠 2000mg · 钙 800mg。
例：巨无霸钠 961mg = 每日参考值的 48%。这是**单品构成展示，不做累计记账**。

### P1 · 让数据活起来

**目标**：摆脱静态快照，让图鉴始终反映当下在售的真实商品。

| 功能 | 说明 | 数据来源 |
|---|---|---|
| **数据刷新通道** | 见下方三种方案 | `list-nutrition-foods` + `campaign-calendar` |
| 门店 → 菜单 | 定位后拉该店可售餐品，图鉴条目加"当前是否供应"标记 | `query-nearby-stores` → `query-meals` |
| 真实到手价 | 选商品试算实际支付金额 | `calculate-price` |
| 新品自动入库 | 活动日历里的新品自动成为新卡 | `campaign-calendar` |

**数据保鲜的三种方案（需要你选一个）**

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| A 手动刷新 | 你说一句，我重新拉并更新 `data.js` | 零基础设施 | 需要记得刷 |
| B 打开时拉取 | 页面加载时调 MCP | 永远最新 | 浏览器需持有 token，**有泄露风险** |
| C 本地代理 | 起一个本地服务转发 MCP 请求 | 最新且 token 不外泄 | 需要跑一个进程 |

**我的建议是 A**。当前数据是 2026-10-10 的快照，营养表变化很慢（一两个月刷一次就够），为它跑常驻服务不划算。B 会把 token 写进前端，明确不推荐。

**验收**：刷新后新品出现在图鉴且被正确标记为当季限定。

**工作量**：约 1 个迭代

**目标**：从"能查"到"好查"。

| 功能 | 说明 | 数据 |

有了 P0–P2 的数据基础，这一层几乎零成本：

## 四、技术架构

```
┌────────────────────────────────────┐
│ 前端 · 单屏 App Shell                │
│ 抽奖 / 图鉴 / 活动 / 我的            │
└────────────┬───────────────────────┘
             │ MCP over HTTPS · Streamable HTTP
             │ Authorization: Bearer
┌────────────▼───────────────────────┐
│ 官方服务 https://mcp.mcd.cn          │
│ 35 工具：门店/菜单/价格/积分/         │
│        活动/营养/抽奖/派对            │
└────────────┬───────────────────────┘
             │
┌────────────▼───────────────────────┐
│ 本地持久化 SQLite                    │
│ 抽卡记录 / 捕获 / 亲密度 / 快照       │
└────────────────────────────────────┘
```

### 踩过的坑（记下来省时间）

**MCP 接入**
- `~/.workbuddy/mcp.json` 里 `type` 必须写 **`streamable-http`**，写 `http` 不生效
- 端点 `https://mcp.mcd.cn`（`/mcp` 是 404）
- 改配置后需**完全退出再重开**客户端
- 实例 id `custom-mcp:mcd-mcp`，启动自动 connect，无需手动信任
- `calculate-price` 返回金额单位是**分**，展示 ÷100
- 限流 600 req/min/token

**前端**
- 单屏布局：`main` 必须 `flex:1 1 auto; min-height:0`，否则不滚动
- 事件一律用 `addEventListener` 委托，**不用内联 onclick**
- **`localStorage` 必须 try/catch 包裹** —— 预览/沙箱环境会抛 SecurityError，一抛整个脚本崩溃，表现为"所有按钮点不动"
