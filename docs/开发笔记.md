# 开发笔记

记录实现结构、关键参数和踩过的坑。想改代码前建议先看一遍。

---

## 一、整体结构

`index.html` 里只有一个 `<style>`、一个 `<body>`、两个 `<script>`：

```
index.html
├── <style>                        # 全部样式（约 400 行）
├── <body>
│   ├── header                     # logo + 居中页名
│   ├── main
│   │   ├── #p-lot   抽奖
│   │   ├── #p-dex   图鉴
│   │   ├── #p-cart  购物车
│   │   ├── #p-camp  活动
│   │   └── #p-go    汉堡GO
│   └── nav                        # 底部 5 个页签
├── <script>  数据层                # window.MCD_* 五个变量
└── <script>  (function(){ ... })() # 应用逻辑，整体包在一个 IIFE 里
```

**注意：应用逻辑在 IIFE 内**，`showPage` / `goStart` / `priceOf` / `NUTRI` 等都不是全局变量。
想从控制台或外部脚本调用，必须把调试代码注入到 IIFE 内部（见第五节），
直接在 `<script>` 末尾追加代码是调不到的。

页面切换：`showPage(page)`，`page` ∈ `lot | dex | cart | camp | go`。
它直接写内联 `style.display`，不依赖 class —— 部分 webview 内核对 class 切换不生效。

## 二、数据层

`NUTRI` 是核心数据结构，由 `MCD_NUTRI_RAW` 解析而来：

```js
{
  n: '猪柳麦满分', d: '能量描述',
  kcal, pro, fat, carb, na, ca,
  cat: '堡类',          // 属性分类，8 类
  rar: 'SR',            // 稀有度
  score: 600,           // 唯一数值评分 0–999
  id: 12                // 数组下标，作排序终判，保证 sort 稳定
}
```

- `rar` 由 `rarity(x)` 算出，规则见 README，**没有隐藏权重表**
- `score` 由 `RSCORE_BASE = {N:0, R:200, SR:400, SSR:600, LIM:800}` + 档内热量降序累加，
  保证全局唯一，用于「稀有度」排序
- `cat` 由 `cat(n)` 用正则关键词匹配名称得出，「其他」是兜底

价格匹配 `priceOf(n)` 用 `normName()` 归一化 + 双向子串包含，详见 `docs/数据说明.md`。

## 三、抽卡

```js
PITY_MAX = 10                       // 累计保底阈值
RWEIGHT  = {LIM:2, SSR:6, SR:16, R:36, N:40}   // 权重，和恰好 100，页面上直接当概率展示
```

- `pick(pool, forceHigh)`：`forceHigh` 或 `ST.pity >= PITY_MAX-1` 时，把池子收窄到
  SR+ 并标记 `forced`
- 十连：逐张抽，若 10 张里没有 SR+，第 10 张强制替换
- 抽卡不调任何接口，纯本地随机

抽奖次数（`ST`，持久化在 `localStorage` 的 `mcdex_stat`）：

```js
ST = {
  total, pity, rar: {N,R,SR,SSR,LIM},   // 出货统计
  draws: 10,                            // 剩余次数（首次进入送 10 次）
  used: 0,                              // 累计消耗
  earned: 0,                            // 累计从汉堡GO获得
  goBest: 0                             // 汉堡GO 历史最佳格数
}
```

所有新字段都有 legacy 兜底（`if(typeof ST.x !== 'number') ST.x = 0`），
老玩家的存档升级后不会出 NaN。

## 四、汉堡GO（跳一跳）

### 状态机

```
ready ──goStart()──> idle ──goCharge()──> charging ──goRelease()──> jumping
                       ↑                                              │
                       └──── 踩中下一台面 goScore++ ──────────────────┘
                                                              落空 ↓
over <──goFinish(reason)── jumping / 倒计时归零
  └──goFailAnim(dt) 播 ~0.55s──> goShowOver() 弹结算
```

关键全局（IIFE 内）：`goState` `goPlats` `goCur` `goScore` `goChar{cx,arc,squash,hit}`
`goPower` `goJump` `goCam` `goTime` `goT` `goFail*`。

### 手感参数

| 参数 | 值 | 说明 |
|---|---|---|
| `GO_TIME` | 60 s | 单局限时 |
| 蓄力增速 | `dt * 1.25` / s | 约 0.8 s 蓄满 |
| 跳跃距离 | `70 + power * 340` px | 与抛物线指示线共用同一公式 |
| 跳跃弧高 | `60 + power * 120` px | 同上 |
| 跳跃时长 | 0.52 s | `goJump.dur`，水平用 `easeOutQuad` |
| 相机跟随 | `goChar.cx - goW*0.30` | 指数逼近，系数 `dt*6` |

**抛物线指示线**与真实弹道共用 `dist` / `peak` 公式，所以在 `charging` 阶段采样 20 个点
画出来，落点就是真实落点 —— 这是刻意保证的，改跳跃公式时必须同步改指示线，
否则提示会骗人。

### 一次跳跃的判定

`goUpdate` 里 `jumping` 段推进 `p = t / dur`，`p >= 1` 时比较落点与下一台面区间：

```js
if (to && land >= to.x && land <= to.x + to.w) {  // 成功：吸附到台面内
  goCur++; goScore++; goChar.cx = clamp(...); goChar.hit = 1;
  if (goPlats.length - goCur < 5) goSpawn();      // 前方始终保留 5 个台面
} else { goFinish('fall') }                       // 落空
```

### 绘制

`goDraw()` 每帧全量重绘，顺序：

1. `goDrawBg()` 天空渐变 → 太阳 + 光晕 → 三层视差云 → 14 颗漂浮亮片
2. 各台面 `goDrawIngredient()`：地面投影 + 顶面 3D 帽渐变 + 前脸垂直渐变 + 高光 + 描边，
   按 `layer.t` 区分面包 / 生菜 / 芝士 / 肉饼 / 番茄 / 薯条
3. 抛物线指示线（仅 `charging`）+ 落点目标环
4. 角色 `goDrawChar()` + 表情 `goBurgerFace(mode)`
5. 失败动画的旋转 / 下坠由 `goFailRot` / `goFailY` 施加

**随机数要确定性**：台面上的斑点、芝麻位置用 `(seed * 17) % n` 这类确定性算法，
不要用 `Math.random()`，否则每帧都在闪。

结算时 `goFinish()` 会把 `floor(goScore/10)` 兑换成抽奖次数，写回 `ST.draws` /
`ST.earned` / `ST.goBest`，并立即调用 `renderDraws()` 与 `goHudUpd()`，
保证「抽奖」页和 HUD 上的数字同帧更新。

## 五、踩过的坑

### 1. `localStorage` 必须包 try/catch

预览 / 沙箱 iframe 里访问 `localStorage` 会抛 `SecurityError`。一旦抛在顶层，
**整个脚本停止执行，表现为「所有按钮点不动」**。所以全部走 `LS` 包装：

```js
var LS = {
  get(k, d){ try { return localStorage.getItem(k) ?? d } catch(e){ return MEM[k] ?? d } },
  set(k, v){ MEM[k] = v; try { localStorage.setItem(k, v) } catch(e){} }
};
```

### 2. 单屏布局的滚动

`main` 必须 `flex:1 1 auto; min-height:0`，缺 `min-height:0` 就不滚动（flex 的经典坑）。

### 3. 容量单位

MCP 的 `calculate-price` 返回金额单位是**分**，展示要 ÷100。
`query-meals` 的价格同理。

### 4. 无头浏览器验证的两个坑

用无头 Chrome 做自动化验证时：

- **`requestAnimationFrame` 不会被 `--virtual-time-budget` 推进**。动画逻辑必须暴露一个
  `goUpdate(dt)` 之类的函数手动驱动帧，否则状态永远停在第一帧
- **CSS `transition` / `animation` 也不会被推进**。元素会卡在动画的中间态：
  透明度过渡的元素看起来发灰、`width` 过渡的进度条卡在 0%。
  验证观感时要先 `el.style.transition = 'none'` 再设目标值
- `--screenshot` 不一定等到虚拟时钟走完，最稳的做法是把要验证的状态**同步**构造好，
  不要依赖 `setTimeout`

### 5. IIFE 里的函数外部调不到

见第一节。注入调试脚本的位置是 IIFE 内部初始化尾部
（`try{ showPage('lot') }catch(e){}` 之后），不是在 `</body>` 前追加。

### 6. 微信内置浏览器

微信里打开本地 `file://` HTML 可能不执行 JS，这不是项目 bug，
用系统浏览器或起本地服务即可。

## 六、改代码时的注意事项

- **不要引入框架或构建步骤**。「一个 HTML 文件双击就能跑」是本项目的核心特性
- 改跳跃公式时，同步改抛物线指示线的公式，否则提示线会与实际落点不一致
- 改数据层时，`data/mcd-data.js` 与 `index.html` 内联块要一起改
- 新增持久化字段时，记得在 `ST` 初始化处加 legacy 兜底
- 视觉改动后建议用无头 Chrome 截图确认（注意上面的第 4 条坑）

```bash
# 1. 语法检查：把两个 <script> 块抽出来交给 vm.Script
node -e "
const fs=require('fs'),vm=require('vm');
const html=fs.readFileSync('index.html','utf8');
const blocks=[...html.matchAll(/<script[^>]*>([\s\S]*?)<\/script>/g)].map(m=>m[1]);
blocks.forEach((b,i)=>{ try{ new vm.Script(b); console.log('block',i,'OK') }catch(e){ console.log('block',i,'ERR',e.message) } });

       --window-size=480,900 --dump-dom probe.html | grep -o '<title>.*</title>'

       --force-device-scale-factor=2 --window-size=480,800 \
       --screenshot=shot.png shot.html
```

2 倍像素密度）。
