# 数据说明

## 一、数据从哪来

全部来自麦当劳中国官方 MCP 服务：

| 项 | 值 |
|---|---|
| 端点 | `https://mcp.mcd.cn`（注意：`/mcp` 是 404） |
| 传输 | Streamable HTTP，`Authorization: Bearer <token>` |
| 工具总数 | 35 个（快照见 `data/mcd-mcp-tools.json`） |
| 限流 | 600 req / min / token |
| 抓取时间 | 2026-10-10 |

本项目只用了其中 4 个**只读**工具：

| 工具 | 用途 | 落地变量 |
|---|---|---|
| `list-nutrition-foods` | 餐品营养表 | `MCD_NUTRI_RAW` |
| `campaign-calendar` | 当月活动日历 | `MCD_CAMPAIGNS`、`MCD_CAMP_URL` |
| `query-meals` | 菜单与商品图 | `MCD_PRICES`、`MCD_IMAGES` |

**没有使用**任何写接口（下单、积分抽奖、领券等）。

## 二、字段格式

### `MCD_NUTRI_RAW`

模板字符串，每行一条，`|` 分隔，共 8 个字段：

```
名称|能量描述|kcal|蛋白质g|脂肪g|碳水g|钠mg|钙mg
猪柳麦满分|猪柳加蛋，早餐的黄金搭档|387|23|21|25|846|243
```

解析在 `index.html` 的 `NUTRI` 构建段完成，得到对象数组：

```js
{ n: '猪柳麦满分', d: '能量描述', kcal: 387, pro: 23, fat: 21, carb: 25, na: 846, ca: 243,
  cat: '堡类', rar: 'SR', score: 600 }
```

- `n` 名称，`d` 能量描述（来自接口的营销文案）
- `cat` 属性分类：堡类 / 炸物 / 小食 / 甜品 / 饮品 / 早餐 / 套餐 / 其他
- `rar` 稀有度，由规则算出（见 README）
- `score` 唯一数值评分，按稀有度分档 + 档内热量降序，范围 0 – 999

### `MCD_CAMPAIGNS`

```js
[ '2026-10-10', '活动名', '活动描述', '标签' ]   // 标签：新品 / 限定 / 限时
```

### `MCD_PRICES` / `MCD_CAMP_URL` / `MCD_IMAGES`

名称 → 值 的映射表。价格单位是**元**（接口原始返回是**分**，已 ÷100）。

## 三、价格匹配是怎么做的

营养表的商品名和菜单接口的商品名写法不一致（前者是营养表口径，后者是菜单口径），
所以不能直接按名称精确匹配。`index.html` 里用 `normName()` + 最长公共子串兜底：

```js
function normName(s){
  return String(s)
    .replace(/[（(][^）)]*[）)]/g,'')      // 去掉括号及内容
    .replace(/[【】\[\]“”‘’·・―—~]/g,'')   // 去掉书名号/引号/间隔点
    .replace(/(冰|热|常温|中杯|大杯|小杯|迷你|盒装|罐装|\d+块|块|™|®|-)/g,'')
    .replace(/\s/g,'');
}
function priceOf(n){
  var k = normName(n);
  if (PMAP[k] != null) return PMAP[k];       // 1) 归一化后精确命中
  var best = null, bestLen = 1e9;
  for (var p in PMAP){                        // 2) 双向子串包含，取最短的（单品优先于套餐）
    if (k.indexOf(p) >= 0 || p.indexOf(k) >= 0){
      if (p.length < bestLen) { bestLen = p.length; best = PMAP[p] }
    }
  }
  return best;
}
```

**当前匹配率 106 / 158 ≈ 67%**。未匹配的基本是早餐与季节限定商品，接口里没有报价，
页面显示「未报价」。子串兜底会带来少量误配（把套餐价套到单品上），所以图鉴卡片上的
价格定位是**参考**而非准确值。

## 四、怎么刷新数据

数据是 2026-10-10 的快照，营养表变化很慢，一两个月刷一次就够。

**推荐做法：手动刷新**

1. 在本地 MCP 客户端（如 WorkBuddy）里调用 `list-nutrition-foods`、`campaign-calendar`、
   `query-meals`，拿到最新返回
2. 整理成上面的字段格式，替换 `data/mcd-data.js`
3. 把 `data/mcd-data.js` 的正文（去掉文件头注释）覆盖到 `index.html` 里
   `<script>/* 麦麦图鉴 McDex — 数据层 ... */</script>` 这一整块

第 3 步可以这样机械化完成：

```js
// node inline.js
const fs = require('fs');
const html = fs.readFileSync('index.html', 'utf8');
const body = fs.readFileSync('data/mcd-data.js', 'utf8')
  .replace(/^\/\*[\s\S]*?\*\//, '')          // 去掉 data.js 的文件头注释
  .trim();
const out = html.replace(
  /<script>\/\* 麦麦图鉴 McDex — 数据层[\s\S]*?<\/script>/,
  '<script>' + body + '</script>'
);
fs.writeFileSync('index.html', out);
```

**不推荐的做法**：页面加载时直接请求 MCP。
那需要把 token 写进前端，任何人都能在浏览器里看到并盗用，明确不要这样干。

---

## 五、token 相关

- token **不写入仓库、不写入前端**，只存在于本地 MCP 客户端的配置里
- MCP 客户端配置写在 `~/.workbuddy/mcp.json`，`type` 必须写 `streamable-http`（写 `http` 不生效）
- 改配置后需要完全退出再重开客户端
- 如果 `index.html` 里搜索到任何形如 `Bearer xxx` 的字符串，那是误提交，请立刻作废该 token
